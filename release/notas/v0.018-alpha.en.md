## ⚽ What it's about

v0.017 installed the Sider module that copies the game database on its own, but on some PCs **the copy never actually got saved**. This version fixes that, and it's already been tested end to end on a real PC: the game copied **27 database files** and the editor recognized **20,174 players from 748 teams**, each with their shirt number.

Also, the player's YouTube video has moved to a spot where it doesn't get in the way.

---

## 🔧 Why the copy wasn't being saved

Sider gives its modules a limited version of `io`, the Lua function for opening files. On some installs that version **won't let you create or overwrite files**: it returns nothing and doesn't even say why. In `sider.log` it looks like this:

```
[edit21_db] ERROR no puedo escribir: ...\content\edit21-db\ -> nil
```

It wasn't a Windows permissions issue or the antivirus: in the same log it happens to other modules too, like **UIColors** (can't save its menu files) and **PostProcessingEditor** (can't save its cache).

## ✅ What module v1.5 does

| | What it does | Details |
|:-:|---|---|
| 1️⃣ | Tries to save the normal way | If it works, it keeps going like that, as always |
| 2️⃣ | If Sider won't allow it, it writes using Windows functions | It uses LuaJIT's `ffi`, which your game already has enabled with `luajit.ext.enabled = 1` in `sider.ini` |
| 3️⃣ | Doesn't touch anything while Sider is starting up | It only picks the folder once the game loads the first database file, and creates it if it doesn't exist |
| 4️⃣ | Logs everything in `sider.log` | Which method it used (`metodo: ffi`) and one `copiado ...` line for each file |

> [!NOTE]
> It's still **read-only**: it doesn't change anything in the game or your game files. It just saves a copy of what the game already loads, in `content\edit21-db`.

### How to update it

1. Open PES Editor and click **Connect Sider folder**. The editor replaces the old module with v1.5 and saves the previous one as `edit21_db.lua.anterior`.
2. Open **PES 2021 with Sider** and get to the **main menu**.
3. Go to **Match › Friendly** up to **team selection** and close the game.
4. Go back to the editor and click **"Done: read again"**.

If everything went well, in `content\edit21-db` you'll see `PlayerAssignment.bin`, `Player.bin`, `Team.bin` and the rest of the database, with a just-now timestamp.

## 📋 Database squads, verified with real files

Until now the editor guessed how `PlayerAssignment.bin` was laid out, the file that says which player is on which team. With the real copy from the game, the format was confirmed:

| Bytes | What it stores |
|---|---|
| 0 – 3 | Row number |
| 4 – 7 | Player ID |
| 8 – 11 | Team ID |
| 12 | Shirt number (the game counts from 0: number **1** shows up as **0**) |
| 13 | Order within the squad |

The editor recognizes it directly and **calibrates the shirt number by comparing against the squads in your EDIT**: in the test, all 20,174 players matched. Teams that are empty in your EDIT show the game's squad with the correct shirt number.

## 🎵 YouTube video above the player

With the player minimized, the video now goes **above the bar**, in the free space on the left, and uses all the width available (minimum 200 × 200, which is what YouTube requires). On narrower screens, where that gap doesn't exist, it stays on the side so it doesn't cover the team list. Nothing changes on phones: the video only shows with the panel open.

## 💬 The editor's warning, clearer

If `sider.log` shows the error from an older version of the module, the warning no longer sends you off to check ransomware protection: it explains what happened and that repeating the steps is enough. Also, the help lines the module leaves are no longer mistaken for a permissions error.
